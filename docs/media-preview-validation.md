# Media Preview 验证记录

日期：2026-11-15。插件版本：0.1.0，宿主基线：Paseo 0.15.4。

## 文件上限与界面调整（同日更新）

- 当前上限为 **1 GiB**，下方初版记录中的 64 MiB 已被替代。仍通过宿主接口完整读取文件，没有改为流式播放器。
- 删除面板内重复文件标题、类型标签、圆点分隔和常驻说明。底部使用紧凑的文字操作，尺寸与文件大小依靠间距排列，播放时长继续由播放器显示。
- 同一文件在读取期间连续变化时，只保留一次后续读取，旧结果不再进入播放器，避免并发读取多个大文件版本。删除会清除待处理读取。
- 类型检查和 9 个单元测试通过。1 GiB 允许、超过 1 GiB 拦截使用模拟文件句柄验证，并非实际传输了 1 GiB。
- Chrome 155.0.8059.84 的浏览器测试通过，包含真实 96 MiB MP4 完整传输和播放。该样本是在有效 H.264/AAC MP4 后追加合法 ISO BMFF `free` box，验证的是文件大小与传输路径，不代表长视频编码性能。
- 查看了深色宽屏、浅色 375px 窄屏以及 96 MiB 文件的截图；没有圆点分隔或横向溢出。MP4、WebM、MP3、WAV 和现有播放器交互回归通过。
- 本机插件重新加载成功，状态为 `running`，未重启 daemon。

## 实现

- 独立插件：`plugins/media-preview`，文件标签页入口，client-only，没有服务端进程、RPC、自动发送消息或会话操作。
- 播放、暂停、进度和音量使用浏览器媒体控件；插件补充前后十秒、循环、0.5× 至 2× 速度、时长和视频尺寸。
- 注册 15 种音视频扩展名，实际解码由客户端决定。不进行转码。
- 使用宿主文件句柄，限制读取前大小为 64 MiB；远程文件也会完整下载至客户端，不是流式预览。读取过程无取消 API，文件并发替换时不能承诺硬性内存上限。
- 中文、英文及主题颜色；浏览器 API 仅在 `client/web.ts`，iOS/Android 提示不可用且不读取媒体。

## 验证证据

1. 插件 TypeScript 检查通过，7 个自动测试覆盖超限/空文件/不支持类型的读取前拦截、删除与重建、读取竞态、卸载清理、文件增长、读取失败恢复、拒绝外部 URL 和时长格式。
2. 官方 v0.15.4 源码的 `compileDirectoryPlugin` 编译成功，只有 client bundle，server bundle 为 null。
3. `scripts/media-preview-browser.mjs` 在 Google Chrome 155.0.8059.84 中通过。使用真实 React Native Web 面板和生成样本，文件句柄及翻译上下文为测试替身。验证 MP4/H.264/AAC、WebM/VP9/Opus、MP3、PCM WAV 的解码及播放时间推进，以及不自动播放、跳转、倍速、循环、删除重建、解码失败、大小限制和卸载暂停。
4. 同一浏览器检查生成并查看深色宽屏、浅色 375px 窄屏截图，未出现横向溢出。模拟 iOS/Android 分支时读取次数为零；这不是手机真机验证。
5. 安装于本机选定的 Paseo home，`paseo plugin ls media-preview` 返回 `running`，日志为 `Plugin ready`。未重启 daemon。
6. 通过 Paseo macOS 桌面实际文件链接打开 MP4，显示文件名、大小、15 秒时长和 640 × 360 尺寸；点击播放、静音、前进十秒和 1.25× 后，实际画面到达约 10.7 秒，控件为暂停状态。音频播放在浏览器测试中验证，未完成 Paseo 桌面音频标签页的独立交互验证；未验证物理音频输出、手机真机、远程宿主或其他操作系统。

复现：从工作区根目录运行 `pnpm --filter @paseo-plugins/media-preview test:browser`。需要 Chrome 和 FFmpeg；输出包含临时截图目录。本机手工验证样本位于已忽略的 `.media-preview-qa/`。

接口依据：[Paseo 文件面板](https://paseo.sh/docs/plugins/reference#file-panels)、[客户端运行时](https://paseo.sh/docs/plugins/reference#runtime-modules)。实现同时对照已安装 0.15.4 类型和官方 v0.15.4 源码，未假设官网新增接口已经包含在本机版本中。
