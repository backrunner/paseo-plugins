# SubscriptionEvo 实施与验证记录

日期：2026-11-15。源码及当前加载版本：0.1.5 开发版。已按用户授权重载成功，未重启 daemon 或发送测试消息。续跑在插件设置，目标只从 `/evo-goal` 打开；输入区浮层专注稍后发送。

## 已实现

| 能力 | 行为 |
| --- | --- |
| 输入入口 | composer 的“稍后发送”浮层和有内容时的“队列 · N”；续跑在插件设置，目标由 `/evo-goal` 打开 |
| 消息队列 | 持久化、严格 FIFO、编辑前暂停、原位保存、撤回、恢复、上移、发送历史 |
| 发送时间 | 空闲、指定时间、额度恢复后固定或随机分钟数；到时仍需满足空闲、权限与授权条件 |
| 临时错误 | 所有 provider 共享保守分类；30 秒指数退避，基数最多 10 分钟，加 0–20% 抖动，尊重错误中的数字 Retry-After 秒数 |
| 额度失败 | 未完成回合的明确 quota 错误生成恢复消息；已有消息则保留正文和原定时间，加额度恢复条件，不插入重复 continue |
| 通用目标 | 有期限与回合预算；每轮带随机校验标识的文本进展报告；完成、暂停、阻塞、无进展、预算耗尽状态 |
| UI | Paseo 原生 popover / compact sheet，宿主负责定位、内边距与滚动；SettingsSection、SettingsSwitch、SettingsSelect、SettingsInput、TextInput；主题色、中英文与错误边界 |
| 开发命令 | 显式 `--home` 的安装与更新；`--dry-run` 不读目标、不连接；更新只 reload 此插件 |

首版统一使用文本报告，没有 `agent.open.before` 工具注入，因此安装或重载不会为了注入工具而将所有会话标记为需要重开。`/evo-goal` 打开目标表单，管理动作在面板中完成，没有注册或接管原生 `/goal`。

## 输入区交互与版本边界

“稍后发送”使用 `addComposerPill` 的 `popover` behavior，直接在当前会话旁填写消息、选择发送条件并入队；常用流程不调用 `openPanel`。指定时间提供本地日期时间及快捷延迟，额度恢复提供分钟范围。原生输入框中的普通草稿和附件保持由 Paseo 管理。

0.1.2 移除浮层里的续跑和目标导航；日期、时间分列，额度最少/最多分钟具有可见标签；一个主操作安排发送，一个次操作仅排队。按钮组件保持稳定身份，轮询刷新不会重建按钮组件。`addSettingsScreen` 将续跑放到宿主插件设置页，必须选择会话后才展示设置；`/evo-retry` 进入同一页。`/evo-goal` 打开独立的目标表单，提交前仍保留 Codex 原生 goal 互斥确认。

0.1.3 根据用户截图收紧布局：用紧凑的三段选择替代设置页尺寸的发送条件行；快捷时间使用小按钮并显示选中状态；日期与固定宽度的本地时间对齐；主操作收在右侧，正文说明缩为一句。颜色全部来自宿主主题，自动发送和队列语义没有改变。

0.1.4 的待发送消息直接提供“编辑 / 撤回”。后端先确认消息仍为 queued 并持久化暂停，客户端才打开编辑器；保存仍复用原条目及顺序，可选“保存并暂停”或“保存并安排”。关闭、放弃或插件重载均不会自行解除暂停。编辑草稿和新消息草稿分开保留，切换会话或重开浮层不会相互覆盖；未提交修改仍只保留在客户端内存。只修改正文不会重抽额度恢复的随机延迟；修改发送时间同步更新过期时间。

0.1.5 修复宿主入口把 `{count}` 原样显示的问题，改用 `{{count}}` 插值，并使用安装的 0.15.4 `PluginTranslationRuntime` 验证英文、中文、语言切换和计数更新。旧测试的自制替换函数与宿主行为不一致，已移除。浮层顶部改成标题与带计数的紧凑入口；队列采用宿主主题卡片，时间精简到本地日期和分钟，编辑/撤回直接可见，其余操作在“更多操作”中展开。单条消息不再重复显示整行暂停，空历史不显示入口。有编辑草稿时点击队列仍打开列表，可从条目继续编辑。

编辑保存使用持久化请求回执和版本检查，断线重试不重复安排，也不恢复后来撤销的发送授权。并发修改要求检查后重新取得暂停状态。撤回先使正在进行的发送检查失效，再核对版本及未发送状态；成功后移出队列、原文保留在历史中。dispatching / unknown 不提供撤回，unknown 的“检查后移出队列”仅清理记录，不宣称撤销已提交的消息。

0.15.4 的 [`PluginClientContext`](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/plugin/src/client/contracts.ts) 和 [`PluginButtonContentProps`](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/plugin/src/client/buttons.ts) 不包含原生草稿读写或提交拦截接口。当前网站已有更新的 composer API 文档，不能据此假定已安装的 0.15.4 可用。要直接给原生草稿设置发送时机，需兼容宿主提供这些接口后另行实现；当前没有 DOM 注入或私有 store 修改。

下方工具栏也没有插件插槽：宿主的 [`AgentTracks`](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/app/src/panels/agent-tracks.tsx) 渲染插件 pills，而 [`agent-panel`](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/app/src/panels/agent-panel.tsx) 将该轨道放在 composer 上方。注册参数没有位置选项，因此当前保持官方入口位置。

队列计数只包含 `queued`、`dispatching`、`unknown`，排除其他会话和终态历史。零条时 `visible: false` 移除入口及布局空间。单个客户端每个宿主共享一次计数读取，通常间隔 5 秒；本地操作成功后立即刷新。计数读取仅访问插件内存，不查询额度或模型。网络错误保留最后已知入口；目录刷新保持按钮注册身份，避免把打开的浮层关闭。

浮层的未提交正文按 host/agent 保存在客户端内存，关闭再打开可恢复；进程退出或插件重载后不保留。未确认入队会保留请求 ID 并锁定原文与发送条件，重新提交不会创建第二条。已入队正文仍使用后端持久化队列。

Review 修复：过去时间先在客户端拒绝，不锁表单；新增 `queue.submit` 区分明确的写入前拒绝和结果不明的 RPC/存储错误，前者允许修正，后者保持原请求。后续查询确认同一请求已入队后，界面自动解除未确认状态。视图按 host/agent 显式重建，避免复用组件时把旧会话草稿带到新会话。原 `queue.add` 契约保留兼容。

## 发送与恢复保护

1. 连接只接受已选择 home 内记录的 loopback endpoint，握手核对 server ID、精确版本和权限上限。只读连接请求 `daemon.read`、`workspace.read`；每次发送单独建立含 `workspace.write` 的连接并关闭。没有 daemon 管理、终端、权限回答或 provider 切换接口。
2. `automatic`、`retry`、`quotaResume` 默认全为 false，goal 为 null。“安排发送”在同一次持久化入队中只授权这一条消息；“仅加入队列”将该条设为暂停，即使会话已开自动发送也等待后续授权；`/evo-send` 沿用会话策略。原始授权意图参与请求去重，重试已暂停的请求不会恢复其发送权限。“允许按条件发送”也保留原定时间和额度条件。取消、暂停与新事件会使尚未发送的检查失效；已经到达宿主的消息无法撤回。
3. 两次稳定空闲观测间隔至少 2 秒，写连接再读一次状态。归档、内部会话、provider 不可用、活动回合和待处理权限均阻止发送。普通输入、provider/session 身份变化、取消和关闭暂停托管。
4. 发送前先持久化稳定 message ID、精确正文与 dispatching 状态。无法确认结果时置为 unknown；重启后遗留 dispatching 也转为 unknown，不自动重发。查询历史找到同一 ID 后仍要求检查再恢复。
5. 每会话额度查询最多每分钟一次，全安装最多每 5 秒发起一次。只接受一个明确报告、120 秒内的有效时间戳，以及所有窗口明确为正的余额。当前报告不能早于任务入队或最近的 quota 失败/耗尽观测。多个候选报告、未知余额、过期信息和账户 ID 变化都不授权发送。
6. 临时重试与 quota 恢复共用连续恢复次数预算，默认 5、上限 10。成功回合重置；新的人工作业边界或新建目标可开始新的预算。目标另受总回合与到期时间限制，默认 10 回合、24 小时。
7. 原生 Codex goal 无公开的可靠活动查询供本实现使用，互斥依靠用户明确确认已关闭。插件不会调用原生 goal 的暂停、清除或设置接口。这是使用前提，不是技术上证明其已关闭。

## 持久化与容量

状态位于已绑定 home 的 `subscription-evo/state.json`。POSIX 目录权限 0700、文件权限 0600；临时文件落盘、fsync、rename、目录 fsync；单写者锁防止两份调度器同时工作。数据校验或存储失败时停止发送，不覆盖损坏状态，不自动删除历史。锁被破坏时进入故障状态。

固定存储目录意味着同一 home 只支持一份此插件调度器；不是多个安装 ID 各自运行独立队列。源目录不保存用户消息或凭据。状态包含排队正文和目标报告，没有读取或保存 provider OAuth token。绑定时仅后端读取 Paseo 的本地连接凭据，客户端不会收到凭据。

首版每个 home 最多保留 500 条消息记录（包括终态历史）、100 个会话策略和 8 MB 状态，达到任一上限拒绝新增。没有自动清理、迁移或备份。要重置，应先确认没有在途或结果不明的消息，禁用插件，再自行备份并移走该插件状态目录，重新启用后重新配置会话策略。不要在插件运行时编辑状态文件。

消息默认 7 天过期；指定时间消息至少保留到该时间后 24 小时，最多可指定一年以内的时间。自动回合结束事件不支持宿主重放；插件离线期间错过的失败不会被猜测为需要续跑，未完成目标可能需要人工检查并恢复。

## 留给人工的验收

建议先选独立开发 daemon，不需要操作当前工作中的实例。

1. 按根 README 预览、安装或更新，检查 `running` 和插件日志；打开一个专用测试会话的“稍后发送”，首次使用时绑定 home。
2. 在浅色、深色及窄窗口确认按钮、列表、输入、错误提示和滚动与 Paseo 一致；确认普通 composer 草稿不受操作影响。
3. 空队列时只保留“稍后发送”。选“仅加入队列”排入未来消息，确认出现计数且到时不自动发送；选“安排发送”或明确授权已有消息后，确认空闲时只收到一次，原文一致，自动续跑开关仍关闭。发送完或取消后队列入口消失，普通输入继续留在同一会话。
4. 在插件设置明确选择专用测试会话，启用自动模式，验证编辑、排序、暂停、取消，和 agent 正在运行、存在权限请求时的等待；确认新普通输入会暂停托管，其他会话策略没有改变。
   编辑消息后关闭浮层，确认到时仍暂停；重新打开修改正文和时间，分别检查“保存并暂停”和“保存并安排”。撤回最后一条消息后入口隐藏，历史保留原文。编辑不覆盖另存的新消息草稿。
5. 在专用测试 provider 验证一次临时失败和 quota 失败。没有真实 quota 测试条件时，不据此声称额度恢复已在该 provider 验收。
6. 关闭客户端后检查插件后端仍按条件工作；在独立实例中检查插件重载和进程异常后的恢复，确认结果不明的消息不重复发送。
7. 为短任务设置有限 goal，确认报告、证据、暂停和预算；Codex 先关闭原生 `/goal`。测试带附件时不要提交 `/evo-*`，使用插件面板。

仍不能消除最后一次空闲检查之后与其他客户端的发送竞争，也不能观测其他客户端尚未提交的原生队列或可靠识别外部登录切换。这些是当前不修改 Paseo 的接口边界。
